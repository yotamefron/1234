## TECH VALUES SHEET (ערכים טכנולוגיים)

**Hidden sheet.** Freeze: A2. Hidden col: Q. 17 columns.

### Persistence mechanism (CRITICAL)

**Problem**: If inventory rows are reordered, tech values entered for specific products get scrambled.

**Solution**: Column A is **manual input** — the user (or populate_data.py) enters the item's unique ID. All other columns use `MATCH(A{r}, inventory!D, 0)` to look up the item. When inventory order changes, the MATCH still finds the correct item by ID.

**Principle**: Tech data is keyed by item ID, not by row position. This is fundamental to the design.

### Columns

| Col | Header | Type | Notes |
|-----|--------|------|-------|
| A | מזהה פריט | **manual input** | Key field — item unique ID |
| B | שם מוצר | formula | INDEX(inv!B, MATCH(A, inv!D, 0)) |
| C | גרסה | formula | INDEX(inv!C, MATCH) |
| D | קו מוצר | formula | INDEX(inv!A, MATCH) |
| E | הדפס צד A | formula | INDEX(inv!M, MATCH) |
| F | MWIR צד A | **manual numeric** | format 0.00 |
| G | LWIR צד A | **manual numeric** | format 0.00 |
| H | NIR צד A | **manual numeric** | format 0.00 |
| I | הדפס צד B | formula | INDEX(inv!N, MATCH) |
| J | MWIR צד B | **manual numeric** | format 0.00 |
| K | LWIR צד B | **manual numeric** | format 0.00 |
| L | NIR צד B | **manual numeric** | format 0.00 |
| M | נובל | dropdown כן_לא | — |
| N | ממוצע MWIR | formula | AVERAGE of both sides if B exists, else A only |
| O | ממוצע LWIR | formula | same |
| P | ממוצע משולב | formula | AVERAGE(N, O) |
| Q | סינון_צדדים | formula (hidden) | Cross-filter helper — see below |

**IMPORTANT — NIR is standalone**: NIR does NOT enter any average calculation. It stands alone. The combined average (P) is only MWIR+LWIR.

### Column Q — Cross-filter formula

Checks if all 8 side-specific filter cells (TechOps row 8, A8:H8) are empty → returns 1.
Otherwise checks two combinations:
- Side A matches Profile 1 (A8:D8) AND Side B matches Profile 2 (E8:H8)
- OR Side B matches Profile 1 AND Side A matches Profile 2

Each side check uses `_sm()`: 4 range conditions (MWIR min/max, LWIR min/max).

**Principle**: Physical sides are interchangeable — it doesn't matter which physical side is which, as long as one matches each profile.

## CRITICAL PRINCIPLES (audit against these)

1. **Per-side filtering**: When filtering by tech value min/max, show the item if AT LEAST ONE SIDE meets the criteria. The pattern is: `(sideA >= min) + (sideB >= min) > 0`.

2. **Interchangeable sides (cross-filter)**: Physical sides A and B are interchangeable. When defining "Profile 1" and "Profile 2", the item passes if (A matches 1 AND B matches 2) OR (B matches 1 AND A matches 2).

3. **Tech values persistence**: Tech data is keyed by item ID (column A = manual input), not by row position. All lookups use MATCH. Reordering inventory does NOT scramble tech values.

4. **NIR is standalone**: NIR does NOT participate in any average. The combined average (P) is AVERAGE(MWIR_avg, LWIR_avg) only. NIR appears as separate columns in the detail view.

5. **AJ/AK helper columns**: Dashboard summary metrics use pre-computed per-row scalar helpers (AJ/AK) in the inventory sheet, NOT massive inline array formulas. This is the solution to formula-too-long errors.

6. **TechOps is independent**: The TechOps dashboard uses its own inline T_ENV formula, not the regular dashboard's AE helper. The two dashboards don't interfere with each other.

7. **Settings extensibility**: Every settings table has padding rows included in the Named Range. Users can add new values directly in Excel.

8. **Freeze behavior**: TechOps dashboard freezes at A9 (below all 8 filter rows). The summary section scrolls WITH the detail — it is NOT frozen.

9. **Loans section is unfiltered**: The active loans sections in both dashboards always show ALL loaned items regardless of filter state.

10. **Yellow partial env match**: When an environment is selected and a two-sided item has only ONE side matching that environment, the entire detail row is highlighted yellow. This is a visual alert.

11. **Don't break existing features**: Every feature that currently works must continue working. No regressions.
